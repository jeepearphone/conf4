# Ассемблер и интерпретатор УВМ · вариант 11

## Общее описание

Ассемблер читает программу в формате CSV, переводит команды в список
инструкций с полями A и B и записывает машинный код в двоичный файл.
Интерпретатор выполняет команды загрузки, чтения, записи и унарного минуса.

По модели УВМ память команд содержит байты программы, а память данных —
524288 ячеек с начальным значением 0. Аккумулятор и ячейки хранят знаковые
32-битные целые. Унарный минус учитывает переполнение по модулю 2³².
Поэтому отрицание минимального значения −2147483648 снова даёт −2147483648.
Исполнение последовательное, до конца программы. Недопустимый адрес,
неизвестный код или обрыв инструкции считаются ошибками выполнения.

## Язык и параметры ассемблера

Первая непустая строка CSV — `command,operand`. Далее на каждой строке
записывается одна команда. Кодировка UTF-8, допускается BOM. Пустые строки
пропускаются. Пробелы по краям полей игнорируются. Регистр мнемоник значим.
Операнд — целое число в десятичной записи или с префиксом `0x` либо `0X`.
Например, `read,044` и `read,0x2C` означают одну и ту же команду.

| Мнемоника | A | Диапазон B | Действие при исполнении |
| --- | --- | --- | --- |
| load_const | 6 | 0..511 | Загрузить B в аккумулятор |
| read | 4 | 0..127 | Прочитать в аккумулятор ячейку по адресу аккумулятор + B |
| write | 5 | 0..524287 | Записать аккумулятор в ячейку B |
| neg | 1 | 0..524287 | Загрузить в аккумулятор значение ячейки B с минусом |

Запуск из корня проекта после настройки `PYTHONPATH`:

```text
python -m uvm.assembler SRC OUT [--test]
```

`SRC` — исходный CSV, `OUT` — путь для записи машинного кода. После
успешной записи ассемблер печатает количество команд. Флаг `--test`
дополнительно выводит байты каждой инструкции отдельной строкой перед итогом.

Неверный заголовок, неизвестная команда, ошибка синтаксиса CSV, лишний
или пропущенный столбец, неверное число или выход за диапазон приводят
к сообщению в stderr с номером строки и ненулевому коду завершения.

### Формат машинного кода

Файл содержит команды подряд в порядке строк CSV. Заголовок и разделители
отсутствуют. Биты нумеруются от младшего, начиная с нуля. Поле A занимает
биты 0–2. Слово команды вычисляется как `(B << 3) | A` и записывается
младшим байтом вперёд. Свободные старшие биты равны нулю.

| Команда | Биты B | Длина в байтах |
| --- | --- | --- |
| load_const | 3–11 | 2 |
| read | 3–9 | 2 |
| write | 3–21 | 3 |
| neg | 3–21 | 3 |

### Запуск интерпретатора

```text
python -m uvm.interpreter PROGRAM DUMP --range START:END
```

`PROGRAM` — двоичный файл ассемблера. При каждом запуске аккумулятор
и память данных обнуляются. Первая инструкция начинается с байта 0.
`DUMP` — путь к выходному JSON-файлу. Обе границы диапазона включительны:
`--range 10:10` сохраняет одну ячейку. Допустимые адреса — от 0 до 524287.
Дамп создаётся после успешного исполнения и содержит массив объектов
с адресом и значением каждой ячейки в порядке возрастания адресов.
Ошибка выполнения выводится в stderr, код завершения равен 1.

## Подготовка и проверка

Требуется Python 3.11 или новее. Сборка не требуется. Для разработки
установите pytest и Ruff в активное виртуальное окружение:

```text
python -m pip install pytest ruff
```

В PowerShell выполните `$env:PYTHONPATH = "src"`.
В bash используйте `export PYTHONPATH=src`.
При запуске через GNU Make путь настраивается автоматически.

| Команда | Назначение | Эквивалент без Make |
| --- | --- | --- |
| `make test` | Тесты | `python -B -m pytest -q` |
| `make lint` | Линтер | `python -m ruff check --no-cache .` |
| `make examples` | Сборка примеров и дамп в `results/` | См. примеры ниже |
| `make clean` | Очистка кэшей и каталогов результатов и сборки | — |

## Пример использования

Файл `examples/spec_tests.csv` содержит по одной инструкции каждого вида.

```text
python -m uvm.assembler examples/spec_tests.csv result.bin --test
0xDE, 0x03
0x64, 0x01
0xFD, 0x09, 0x00
0x21, 0x0D, 0x00
Ассемблировано команд: 4
```

Для запуска из корня без настройки пути доступна та же команда через
`python main.py examples/spec_tests.csv result.bin --test`.

Программа `examples/copy_array.csv` заполняет ячейки 100–102 и копирует
их в 200–202. Для чтения каждого элемента она загружает базу 100
в аккумулятор и прибавляет смещение командой `read`.

```text
python -m uvm.assembler examples/copy_array.csv copy.bin
Ассемблировано команд: 15
python -m uvm.interpreter copy.bin dump.json --range 200:202
```

Содержимое `dump.json`:

```json
[
  {"address": 200, "value": 7},
  {"address": 201, "value": 0},
  {"address": 202, "value": 511}
]
```

Программа `examples/neg_demo.csv` записывает 37 в ячейку 300.
Команда `neg,300` помещает −37 в аккумулятор, а `write,301` сохраняет
результат. Повторное отрицание через `neg,301` даёт 37.
В конце программа отрицает ноль и записывает его поверх 37 в ячейке 303.

```text
python -m uvm.assembler examples/neg_demo.csv neg.bin
Ассемблировано команд: 11
python -m uvm.interpreter neg.bin dump.json --range 300:304
```

```json
[
  {"address": 300, "value": 37},
  {"address": 301, "value": -37},
  {"address": 302, "value": 37},
  {"address": 303, "value": 0},
  {"address": 304, "value": 0}
]
```
